# Бесплатный деплой для комиссии

Статус на 23.09.2026: готов PostgreSQL-адаптер, Dockerfile и render.yaml для Render Free + Neon Free. 53 теста прошли с настоящей локальной PostgreSQL, включая версии, конкуренцию, ноль и запрет публичного импорта. Публичного адреса ещё нет: аккаунты созданы, секрет DATABASE_URL капитан вводит непосредственно на Render. Платные ресурсы не разрешены.

## Что сделать капитану сейчас

1. Neon → New project: nomad-coders, Free, регион Frankfurt. Откройте Connect, выберите базу neondb, включите Connection pooling и скопируйте Connection string. Нужна только строка postgresql://… с параметром sslmode=require, без команды psql и окружающих кавычек. Не присылайте её в чат.
2. Репозиторий приватный: Render → New → Web Service → Git Provider → GitHub. Подключите GitHub с Only select repositories и выберите BAITC-Hacks/hack-43bfd950-nomad-coders. Видимость репозитория менять не нужно. Если организация требует Request/одобрение, доступ приложению Render должен выдать владелец организации; собственных прав участника может быть недостаточно.
3. Имя nomad-coders (или свободное), Branch main, Language Docker, Region Frankfurt, Root Directory пустой, Dockerfile Path ./Dockerfile, Instance Type Free. Платный диск не добавлять. Build/Start Command оставьте по Dockerfile.
4. Environment: DATABASE_URL = строка из Neon; NOMAD_DEMO = 1; NOMAD_PUBLIC_DEMO = 1. Health Check Path = /api/health. Нажмите Deploy Web Service. Дождитесь Live.
5. Пришлите только публичную ссылку https://….onrender.com. Она нужна для проверки настоящего HTTPS, обновления страницы, сохранения и CSV. При ошибке присылайте текст build/runtime log без секретов.

Вариант с Blueprint автоматически читает те же параметры из render.yaml и запросит DATABASE_URL отдельно. Не создавайте оба варианта одновременно. Последующие изменения main автоматически пересобираются.

## Предлагаемая схема

Один Render Web Service собирает React и запускает FastAPI; комиссия получает один HTTPS-адрес. Внешняя база Neon хранит наборы, расчёты и версии заказов. Frontend продолжает обращаться к /api; менять его контракт не нужно. Локальная SQLite остаётся для разработки и резервной демонстрации.

Render Free останавливается после 15 минут без входящего трафика; пробуждение занимает примерно минуту. Его локальные файлы теряются при остановке/рестарте, поэтому текущую SQLite нельзя использовать там для сохранения заказов. У Neon есть Free-тариф с постоянной PostgreSQL, сейчас 0.5 ГБ на проект и 100 CU-часов вычислений в месяц. Достаточность этих лимитов для нашего объёма нужно измерить, а не обещать заранее. У обоих сервисов есть ограничения бесплатного использования.

Источники: [Render Free](https://render.com/docs/free), [документация тарифов Neon в официальном репозитории](https://github.com/neondatabase/website/blob/main/content/docs/introduction/plans.md). Условия проверены 23.09.2026; перед созданием выбрать именно Free, не подключать платный тариф.

100% доступность обещать нельзя. Для комиссии можно проверить рабочий сценарий, сохранность заказов после рестарта и открытие после простоя. Перед известным временем защиты открыть сайт заранее и пройти health/CSV; это подготовка демонстрации, не гарантия отсутствия будущего холодного запуска. Локальная версия и короткая запись экрана остаются резервом. Не использовать искусственный трафик для обхода ограничений тарифа.

## Работа капитана перед публикацией

PostgreSQL-адаптер находится в backend/app/storage/postgres.py. При DATABASE_URL сервис выбирает PostgreSQL, без него локальную SQLite. SELECT FOR UPDATE сохраняет атомарную проверку expected_revision; история заказов и расчёты не перезаписываются. Тесты запускаются с NOMAD_TEST_DATABASE_URL на одноразовой базе: каждый создаёт и удаляет только собственную случайную схему.

Dockerfile: Node 24 собирает frontend, Python 3.12 запускает API с зафиксированными зависимостями. .dockerignore включает только исходники приложения и настройки сборки. Процесс работает без root, один worker, адрес 0.0.0.0, порт PORT. backend/app/cloud.py повторяемо загружает фиксированное демо и синтетические наблюдения для настоящего движка, не удаляя заказы. Данные партнёра в образ не входят.

Для начала нужны аккаунты Render и Neon; регистрацию и вход выполняет капитан. Доступ Render к GitHub ограничить репозиторием команды. DATABASE_URL сохраняется в секретах сервиса, не в Git и не в frontend. Платёжные действия не выполнять.

NOMAD_PUBLIC_DEMO=1 запрещает XLSX-импорт с кодом 403 и скрывает несинтетические наборы, расчёты и заказы. Режим требует DATABASE_URL и NOMAD_DEMO=1 и откажется запускаться с временной SQLite. Авторизации и разделения пользователей нет: демонстрационные заказы общие. Наличие внешней ссылки не разрешает публикацию данных партнёра.

## Когда можно передать ссылку комиссии

Проверить по настоящему HTTPS-адресу: главную страницу, refresh вложенного адреса, JSON-404 неизвестного API, рекомендации, объяснение, нулевую правку, сохранение, согласование и скачанный CSV. Затем перезапустить сервис и убедиться, что заказ остался в Neon. Открыть адрес после простоя с другого устройства и отметить фактическое время запуска. Проверить квоты и размер базы.

Для функциональной демонстрации выберите «Расчёт закупки · синтетические наблюдения»: statistical-v1 вычисляет рекомендации, исключает разовый выброс, восстанавливает шесть подтверждённых дней stockout и учитывает приход. Настройки меняют результат. «Учебный склад» — старый фиксированный пример интеграции. Пометка синтетики обязательна в обоих случаях. Публикация на хостинге и сдача через платформу хакатона — разные действия.
