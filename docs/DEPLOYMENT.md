# Бесплатный деплой для комиссии

Статус на 23.09.2026: пользователь требует бесплатную публичную ссылку. Платные ресурсы не разрешены. Сейчас сайт работает локально; публичного адреса ещё нет. Рекомендуемая схема — Render Free для приложения и Neon Free для постоянной PostgreSQL. Подключение этих сервисов ещё не реализовано.

## Предлагаемая схема

Один Render Web Service собирает React и запускает FastAPI; комиссия получает один HTTPS-адрес. Внешняя база Neon хранит наборы, расчёты и версии заказов. Frontend продолжает обращаться к /api; менять его контракт не нужно. Локальная SQLite остаётся для разработки и резервной демонстрации.

Render Free останавливается после 15 минут без входящего трафика; пробуждение занимает примерно минуту. Его локальные файлы теряются при остановке/рестарте, поэтому текущую SQLite нельзя использовать там для сохранения заказов. У Neon есть Free-тариф с постоянной PostgreSQL, сейчас 0.5 ГБ на проект и 100 CU-часов вычислений в месяц. Достаточность этих лимитов для нашего объёма нужно измерить, а не обещать заранее. У обоих сервисов есть ограничения бесплатного использования.

Источники: [Render Free](https://render.com/docs/free), [документация тарифов Neon в официальном репозитории](https://github.com/neondatabase/website/blob/main/content/docs/introduction/plans.md). Условия проверены 23.09.2026; перед созданием выбрать именно Free, не подключать платный тариф.

100% доступность обещать нельзя. Для комиссии можно проверить рабочий сценарий, сохранность заказов после рестарта и открытие после простоя. Перед известным временем защиты открыть сайт заранее и пройти health/CSV; это подготовка демонстрации, не гарантия отсутствия будущего холодного запуска. Локальная версия и короткая запись экрана остаются резервом. Не использовать искусственный трафик для обхода ограничений тарифа.

## Работа капитана перед публикацией

Добавить PostgreSQL-адаптер к storage с тем же интерфейсом. Параметр DATABASE_URL вводится только для облачного режима; текущий код его ещё не поддерживает. Сохранить транзакционную проверку expected_revision, неизменяемые расчёты и историю заказов. Прогнать проверки сохранения, нуля, согласования и конкурирующих правок на PostgreSQL. Расчёт и HTTP от адаптера базы не зависят.

Подготовить Docker-сборку: Node 24 собирает frontend, Python 3.12 запускает API с зафиксированными зависимостями. Исключить исходные Excel, ZIP, .env, локальные базы и окружения. Проверить образ на Linux. Один worker, адрес 0.0.0.0, порт из окружения хостинга; healthcheck /api/health. Демонабор загружается повторяемо при старте в облачную базу, без удаления существующих заказов. Проверить память и время импорта отдельно на ресурсах бесплатного сервиса.

Для начала нужны аккаунты Render и Neon; регистрацию и вход выполняет капитан. Доступ Render к GitHub ограничить репозиторием команды. DATABASE_URL сохраняется в секретах сервиса, не в Git и не в frontend. Платёжные действия не выполнять.

На публичной версии сначала только синтетические данные. Сейчас нет авторизации и разделения пользователей; доступ к настоящим данным и импорту нужно ограничить до их подключения к публичному серверу. Наличие внешней ссылки не разрешает публикацию данных партнёра. Без разделения пользователей демонстрационные заказы в базе общие — это не личный кабинет.

## Когда можно передать ссылку комиссии

Проверить по настоящему HTTPS-адресу: главную страницу, refresh вложенного адреса, JSON-404 неизвестного API, рекомендации, объяснение, нулевую правку, сохранение, согласование и скачанный CSV. Затем перезапустить сервис и убедиться, что заказ остался в Neon. Открыть адрес после простоя с другого устройства и отметить фактическое время запуска. Проверить квоты и размер базы.

До завершения импорта и движка пометка «синтетический пример» обязательна: нынешний каркас не выполняет реальный прогноз. Для итоговой функциональной демонстрации сначала реализовать и проверить бизнес-логику. Публикация на хостинге и сдача через платформу хакатона — разные действия.
