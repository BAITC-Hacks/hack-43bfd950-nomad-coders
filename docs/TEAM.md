# Два исполнителя Nomad Coders

Актуальное решение пользователя: капитан совмещает интеграцию и весь backend; один тиммейт делает frontend. Прежнее распределение на три пишущие задачи больше не применяется.

Капитан работает в исходной папке на codex/api-integration. Он владеет контрактами, API, SQLite, экспортом, импортом Excel, расчётами, зависимостями backend и общим планом. Только он объединяет проверенные изменения в main.

Frontend работает в отдельном clone/worktree codex/web-ui на своём компьютере. Владеет frontend/, кроме frontend/src/api/generated/ — генерируемого общего контракта. Задание: docs/TASK_WEB.md. Новый data-worktree не создаётся; существующую codex/data-engine не удалять, она пока не используется. Задание docs/TASK_DATA.md выполняет капитан после каркаса.

До передачи первого коммита каркаса frontend не меняет общую конфигурацию. После его получения капитан заканчивает только демонстрационный сценарий в заранее обозначенных файлах App.tsx и браузерном тесте; тиммейт начинает с самостоятельных компонентов и сообщает перед изменением тех же файлов. После второго коммита весь интерфейс передаётся тиммейту.

Каждые 30–45 минут — небольшой коммит с работающим результатом и фактическими проверками. Тиммейт делает push только своей ветки; капитан делает fetch, проверяет diff и объединяет в main. Затем тиммейт делает fetch и merge origin/main. Не использовать force push. Не выполнять merge поверх несохранённых изменений.

У каждого своя .venv, node_modules и runtime-база. На разных компьютерах допустимы одинаковые порты 8000/5173. Исходные Excel и базы в Git не добавляются. Личные пути не прописываются в общей конфигурации.

Проверки Codex — ограниченные агенты только на чтение. Независимых пишущих агентов в одной папке не запускать.
