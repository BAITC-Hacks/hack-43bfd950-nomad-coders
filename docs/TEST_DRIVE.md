# Проверка сайта капитаном

Это проверка каркаса 1283425 и последующих визуальных изменений. Реальный импорт и прогноз ещё не подключены. Тестировать на синтетике, не использовать результат как настоящий заказ поставщику.

## Открыть

На компьютере капитана: http://127.0.0.1:8000. Это локальный адрес этого компьютера, не ссылка для другого ноутбука. Если сервер остановлен, из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/seed.ps1
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
powershell -ExecutionPolicy Bypass -File scripts/serve.ps1 -Demo
```

Терминал сервера оставить открытым. Установка зависимостей при первом запуске описана в README. При разработке фронта адрес 5173 обслуживает Vite; 8000 показывает последнюю собранную версию.

## Пройти за пять минут

1. Убедиться, что видна пометка синтетических данных. Если открылся прежний заказ, перейти «1. Данные и настройки».
2. Нажать «Получить рекомендации». Ожидаются 144 шт, 0 шт и «Нет данных». У товара без остатка checkbox выключен.
3. Нажать «Почему?» у DEMO-001. Ожидается объяснение 210 + 70 − 100 − 40 = 140, затем округление до 144 и график вымышленной истории.
4. Создать черновик. Изменить количество DEMO-001 с 144 на 0, написать причину «Проверка капитана». Пока правки не сохранены, согласовать нельзя.
5. Сохранить. Обновить страницу браузера. В заказе должен остаться 0, а исходная рекомендация — 144.
6. Согласовать и скачать CSV. В файле должен быть 0, русский текст и причина правки. Если Excel открыл всё в одной колонке, импортировать как UTF-8 с разделителем «;».
7. Изменить согласованный заказ на 12, сохранить. Статус снова «Черновик», экспорт исчезает до повторного согласования.
8. Проверить ввод -1 и пустую причину: сохранение должно отклоняться. Для положительной правки 1 сервер сообщает о кратности 12. Ноль — допустимое исключение.

Для проверки конфликта открыть тот же заказ в двух вкладках. В первой изменить и сохранить, во второй попробовать согласовать старую версию. Ожидается сообщение, что заказ уже изменён; актуальное значение не затирается. В текущей оболочке после отмены несохранённых правок можно нажать «Загрузить сохранённый заказ».

## Что сейчас считается ожидаемым ограничением

Загрузка XLSX отвечает «Импорт Excel ещё не реализован». Параметры демонстрационного расчёта фиксированы. Фильтры, расширенная панель объяснения и новый дизайн переданы frontend в docs/TASK_WEB.md. Реальные сезонность, рост, выбросы, stockout и даты поставок проверяются после реализации backend. Этот тест не доказывает готовность пяти бизнес-требований кейса.

## Как сообщить об ошибке

Написать действие, ожидаемое и фактическое поведение, номер шага, SKU и версию заказа. Например: «Шаг 5, DEMO-001, версия 2: после refresh ожидал 0, вижу 144». Если есть — приложить текст красного сообщения или скриншот. Не пересылать реальные данные партнёра в публичные задачи.
