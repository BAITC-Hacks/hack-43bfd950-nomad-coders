# Проверка сайта за пять минут

Откройте опубликованный HTTPS-адрес или локальный http://127.0.0.1:8000. Для локального запуска команды setup → seed → build → serve -Demo приведены в README. При повторном посещении может открыться прошлый заказ: перейдите «1. Данные и настройки».

## Основной сценарий

1. Выберите «Расчёт закупки · синтетические наблюдения». Дата 22.09.2026, срок 14, пересмотр 7, запас 7, источник «Транзакции».
2. Нажмите «Получить рекомендации»: SYN-1 — 144 шт, SYN-2 — «Заказывать не нужно», SYN-3 — «Нет данных», выбор отключён.
3. Откройте объяснение SYN-1: потребность 140 округлена до 144 по кратности 12. Приход 40, остаток 100, восстановленный спрос за шесть дней — 60. Разовый документ 10000 исключён; доступны график и допущения.
4. Проверьте поиск по SYN-1, фильтры и сброс. Ноль не должен исчезать как неизвестное значение.
5. Создайте черновик. Замените 144 на 0, причина «Проверка капитана». Сохраните, обновите страницу: 0 сохранился, исходная рекомендация осталась 144.
6. Согласуйте: версия 3. Скачайте CSV; ожидаются ноль, причина, русские заголовки. Excel: UTF-8 и разделитель `;`.
7. Измените 0 на 12 и сохраните. Заказ снова черновик, экспорт требует нового согласования. Число -1 и пустая причина отклоняются. Положительное 1 нарушает кратность 12, ноль допустим.
8. Вернитесь к данным и поменяйте запас на 14 дней. После нового расчёта SYN-1 — 216 шт. Настройки не меняют прежний сохранённый результат.

## Сохранность и публичный режим

Откройте один заказ в двух вкладках. Сохраните изменение в первой; во второй попробуйте согласовать старую версию. Должен быть конфликт, чужая правка не затирается. После явной загрузки сохранённой версии значения обновятся.

Перезапустите сервис и обновите страницу: заказ должен восстановиться из PostgreSQL. Публичная версия показывает только синтетику, справа — инструкция демонстрации вместо загрузки XLSX. На локальной версии доступны известные реальные форматы. Отсутствующий актуальный остаток IEK — ожидаемая блокировка.

## Если что-то не работает

Укажите шаг, SKU, ожидаемое и фактическое поведение, текст ошибки и версию заказа. Не пересылайте пароль Neon, DATABASE_URL или оригиналы партнёра. Если Render просыпается после простоя, дождитесь открытия и повторите запрос; перед защитой откройте сайт заранее.

Для автоматической HTTP-проверки публичного режима из корня:

    .venv/Scripts/python.exe backend/scripts/smoke.py https://ВАШ-СЕРВИС.onrender.com --state runtime/public-smoke.json

После ручного рестарта Render повторите с --verify-restart. Скрипт создаёт один явно синтетический проверочный заказ и проверяет нулевой CSV. Он не отправляет ничего поставщику.
