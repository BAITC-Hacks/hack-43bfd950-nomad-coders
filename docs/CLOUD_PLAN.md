Этот ExecPlan поддерживается по .agent/PLANS.md. Цель — один HTTPS-адрес для комиссии с сохранением согласованных заказов после рестарта. Локальная SQLite остаётся резервом, данные партнёра не публикуются.

## Контекст и порядок действий

Settings читает DATABASE_URL только из окружения. Service выбирает app/storage/postgres.py или прежнюю SQLite. PostgreSQL хранит JSON в таблицах objects и order_versions; SELECT FOR UPDATE блокирует строку заказа до окончания проверки revision и записи. Старые базы не удаляются. Публичный режим требует постоянную базу и включённое демо.

Docker собирает React Node 24, затем запускает Python 3.12 от непривилегированного пользователя. app/cloud.py повторяемо добавляет фиксированное демо и наблюдения app/engine_demo.py для настоящего статистического расчёта. Ни источник, ни Docker-контекст не включают оригиналы партнёра.

Из корня выполнить docker build -t nomad-coders:demo .; запустить с DATABASE_URL, NOMAD_DEMO=1, NOMAD_PUBLIC_DEMO=1. Локальная тестовая PostgreSQL доступна на 127.0.0.1:55432, внутри Docker через host.docker.internal:55432. Тесты backend/tests/test_postgres.py читают NOMAD_TEST_DATABASE_URL и создают только собственные одноразовые схемы.

После проверки опубликовать main. Капитан создаёт Free Web Service по docs/DEPLOYMENT.md и вводит секрет из Neon непосредственно в Render. Публичный адрес — вход для внешней проверки; до его получения не объявлять сайт опубликованным.

## Проверка и приёмка

На реальном HTTP открыть главную и вложенный маршрут, получить JSON-404 для /api/unknown. Вычислить synthetic statistical-v1, сохранить заказ с нулевой правкой и согласовать. Скачать CSV, перезапустить контейнер/сервис и получить тот же заказ. Импорт XLSX возвращает 403. Повторный старт не создаёт дубль набора. На HTTPS повторить браузерный сценарий и отметить фактический холодный старт без обещания 100% доступности.
